# פרטיות, שמירה ושחרור — מה שכחתי?

## עקרונות פרטיות

- תוכן משימות, זיכרונות ושיחות שייך לחשבון בלבד ונאכף ב-RLS.
- ממשק הניהול מציג מדדים ותוצאות תפעוליות בלבד; אין בו תוכן משימות או שיחות.
- קריאות OpenAI נשלחות עם `store:false` ובהקשר מצומצם למשימות פעילות, זיכרונות רלוונטיים, קניות/תזכורות פעילות והיסטוריה קצרה.
- לוגים ואירועי ניטור שומרים מזהים טכניים, קודי כשל, זמני תגובה וספירות בלבד — לא טקסט הודעות.
- הקלטות קול נשלחות לתמלול ואינן נשמרות באפליקציה.

## שמירה ומחיקה

- הודעות באפליקציה מוגבלות ל-200 אחרונות.
- אירועי מצב פנימיים מוגבלים ל-500 אחרונים בבית.
- קבלות idempotency נשמרות עד 7 ימים לצורך מניעת כפילויות בריטריי.
- מדדי AI נשמרים לפחות 7 ימים לצורך דשבורד תפעולי.
- מידע זמני מפסיק להשפיע לאחר `expiresAt`; הוא אינו נהפך אוטומטית להיפוכו.
- מחיקת שיחות/היסטוריה היא פעולה רחבה ודורשת אישור מפורש.

## גיבוי ושחזור

- גיבוי אישי הוא JSON התואם ל-`StateSchema` ויכול להכיל מידע אישי.
- שחזור חייב לעבור validation מלא, להציג תצוגה מקדימה (ספירות משימות/זיכרונות/קניות/תזכורות) ולדרוש אישור לפני החלפת מצב.
- שחזור בענן חייב להשתמש ב-revision הנוכחי; קונפליקט אינו דורס נתונים.

## Checklist לפני Production

1. `npm run typecheck` עובר.
2. `npm test` עובר, כולל `audit-regression.test.ts`.
3. `npm run build` עובר.
4. migrations מותקנות ללא שגיאה על סביבת Supabase נקייה/תואמת.
5. RLS נבדק: pending/blocked אינו קורא או כותב state; approved כן; משתמש אחר לא נגיש.
6. אי אפשר לחסום/להוריד את המנהל המאושר האחרון.
7. `/api/health` אינו חושף שמות/נוכחות של secrets.
8. `/admin` מחזיר 403 למשתמש רגיל בלי למחוק session.
9. אישור גישה, אימות אימייל והרשאת Admin הן פעולות נפרדות.
10. OpenAI: הצלחה, quota, rate-limit, timeout ופלט לא תקין מחזירים קוד מדויק ולא מבצעים שינוי שגוי.
11. ריטריי של אותה פעולת ענן עם אותו idempotency key אינו יוצר כפילות.
12. Push deep-link נפתח ב-`/app?view=reminders`; quiet hours ו-5 ניסיונות נשמרים.
13. דיווח תקלה: סוגי קובץ/8MB/rate-limit/שגיאת רשת נבדקים.
14. responsive smoke: 360, 390, 768, 1440; dialog Escape/focus return; אין חפיפת כפתורים צפים.
15. גיבוי ושחזור נבדקים עם preview+confirm וקונפליקט revision.
16. Production deployment READY, `/api/health` תקין ולוגים ללא שגיאות חדשות.
17. בדיקת Push אמיתית ב-iOS PWA וב-Android/Chrome לפני סימון Push כמאושר לשחרור.
